## 2026-10-26 — Vite 7 → 8 and @vitejs/plugin-react 4 → 6 (re-delivers Dependabot #1109)

- `vite` 7.3.7 → 8.3.5 and `@vitejs/plugin-react` 4.7.0 → 6.1.2, upgraded together: plugin-react 6 requires Vite 8,
  which is why Dependabot #1109 (plugin-react alone) failed `npm ci` with ERESOLVE. The other Vite plugins already
  accept Vite 8 at their current versions (`vite-plugin-pwa` 1.3.0, `@tailwindcss/vite` 4.3.3, `vitest` 4.1.12).
- `vite.config.ts`: Vite 8's bundler (Rolldown) no longer accepts the object form of `manualChunks`, so the four
  vendor chunks (react, supabase, ui icons, mapbox) are now `build.rolldownOptions.output.codeSplitting` groups.
  `react-dom` now lands in `vendor-react` as originally intended (Vite 7 had left it in the main `index` chunk).
- `build.target` pins Vite 7's browser floor (Chrome/Edge 107, Firefox 104, Safari 16.0). Vite 8 raised its default
  to Safari 16.4; pinning keeps older field iPhones/iPads able to load the app.
- `package-lock.json`: npm 11 could not add plugin-react 6 incrementally (it chased an optional Babel 8 peer), so the
  `@babel/*` lock entries were re-resolved; they move only within Babel 7 patch releases (used by the PWA
  service-worker build and a lint plugin, not by the shipped app).
- Proof: production build served locally — app loads, sign-in / password-reset / routing work, the service worker
  registers and precaches every listed file, the "new version" prompt appears, and the app loads with the server
  stopped (offline). Full test suite, typecheck, lint and dependency check pass.
