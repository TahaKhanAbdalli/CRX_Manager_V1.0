## 2026-10-27 - Codex guard: edits in other worktrees, quoted searches, and a real repair path

Codex reproduced three problems with its production-action guard today; each was reproduced again by a real `codex exec` run on unchanged `main` before the fix.

- **Edits in another worktree of the same repository were refused.** A native `apply_patch` could only write inside the checkout the guard file lives in, so a session started in one worktree could not edit a sibling worktree (refused as "outside the repository"). The allowed folders are now every worktree `git worktree list` reports for that repository; an unrelated folder still gets nothing, and if git cannot answer only the checkout itself counts. Every per-file check (protected harness, enforcement surface, review proofs, links, hard links) still applies in each worktree. New: nothing inside a `.git` folder can be patched, because the widening puts the main checkout's git hooks and config inside an allowed folder. (`.codex/hooks/production-action-guard.mjs`: `repositoryWorktreeRoots`, `patchWorktrees`.)
- **Quoted read-only searches were refused.** `rg -n 'git push' AGENTS.md` (Codex guard: "push hidden by shell quoting"), `git grep -n 'apply-migration-file.mjs'` (Codex guard: live apply), and `rg -n "supabase db push" …` (shared `bash-safety.mjs`) all read the quoted pattern as the command it names. New shared `.claude/hooks/read-only-search-lib.mjs` (`literalReadOnlySearch`) recognises a command that only searches and whose every character is literal in bash, PowerShell and cmd.exe; both hooks let it through. Options that start another program (`rg --pre`, `git grep -O`, …), chaining, redirects and substitutions are not recognised, so those commands get every ordinary check. Review-proof files stay off-limits. The helper is added to the Codex guard's protected list (it is imported at startup).
- **Obsolete repair instructions.** Refusals of a harness change told Codex to "use the reviewed maintenance workflow with Mason's approval" (or "use Edit/Write"), but that workflow's script was retired on 2026-09-05 and Codex has no Edit/Write tool. They now say: hand the change to a Claude session, which edits the file on a feature branch and ships it through the reviewed PR in `.claude/commands/ship.md` (Luna, then a fresh exact-head Sol review). This change itself was made that way.
- **Found while proving delivery: a conventional commit message was refused.** Codex's own `git commit -m "docs(changelog): …"` was refused because the fail-closed computed-text rule read the quoted `(` as a subexpression. For that rule only, plain double-quoted text (no `$`, backtick, `%` or `!`) is now treated as text (`literalDoubleQuotedTextBlanked`); substitutions, variables, smart quotes and unquoted `(` still count.

Unchanged: secret protection, review-proof ownership (`review-proof-guard.mjs` untouched), migration protection, the push-to-`main` guard, and every merge gate.

Tests: `read-only-search-lib.test.mjs` (new, wired into `test:correction-guards`), new cases in `production-action-guard.test.mjs` and `bash-safety.test.mjs`. Docs: `docs/reference/agent-guardrails.md`.
