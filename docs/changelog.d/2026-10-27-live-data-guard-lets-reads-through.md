## 2026-10-27 - The live-database guard lets reads through

- **Live-database guard lets reads through** (guard cleanup item 2; Mason, 2026-10-26: "looser guards"). `live-testdata-lib.mjs` now treats the strings of a query as data when nothing in it can run a string as code (no `DO`, `EXECUTE`, `CREATE`, `PREPARE` or `CALL` outside strings and comments): write words or function names inside them no longer cause a refusal. It also allow-lists more read-only catalog, privilege, hash and JSON functions, and stops reading CTE and alias column lists as function calls. Replaying a month of real `execute_sql` calls, refusals of distinct queries fell from 1,069 to 149; the rest are real application-function calls, `set_config` and `query_to_xml`. Write handling is unchanged. Docs: `docs/reference/agent-guardrails.md` (`live-testdata-guard.mjs` row and the read-side false-positives section).
