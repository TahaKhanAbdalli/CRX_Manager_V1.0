## 2026-10-21 — Sol carry-forward: a moved main no longer forces a full Sol re-review

Mason approved "go with carry-forward", then "do your recommendation" for the code-vs-code rule. Every merge into main used to void every waiting PR's Sol proof, because the proof is bound to one head and one base, so parallel sessions kept paying for full Sol reviews again (81 merges to main in the week to 2026-10-21, 23 of them documentation-only).

- `scripts/write-codex-push-proof.mjs --carry-forward` (add `--dry-run` to print the decision only) keeps an earlier clean Sol review for a head that is exactly the conflict-free merge of the reviewed head and today's origin/main. It checks this with `git merge-tree`, so a resolved conflict or a hand edit refuses. The earlier proof must be clean `gpt-6-sol`/`high` and under 24 hours old; behind a chain of carries, the original full review must be too. The source file is re-read and must be unchanged at write time.
- It carries with no model call only when the two sides share no files and one side is plain documentation (the Sol-exempt definition, which excludes every rule file, read from `git diff --raw` so only regular non-executable files count: a symlink, submodule or executable named `*.md` does not). Any other case, including two code changes in different files, runs a focused Sol collision check (`MAIN_DELTA.patch` + `COLLISION_FOCUS.json`). That check starts from the database, guard, CI, dependency and rule files (`CARRY_HOT_PATHS`), counts any other blocker it sees, and carries only on CLEAN.
- `proofValid()` in `.claude/hooks/codex-push-lib.mjs` accepts the carried shape (`codex_ran: false`, `carried_forward: true`, `carry.mode`, `carry.from_head`, `carry.from_base`) on the same exact-head, exact-base and 30-minute terms as a full proof. `pr-merge-guard.mjs` prints `SOL CARRY-FORWARD` when it allows one; its denials and the Codex `production-action-guard.mjs` denials now point at `--carry-forward` (after a merge, not a rebase).
- Docs: AGENTS.md, `.claude/commands/ship.md`, `/codex-review` Step 3B, `docs/reference/agent-guardrails.md`, `docs/manual/AGENT_ONBOARDING.md` and `docs/manual/DECISION_LOG.md`.
- Tests: carried-proof acceptance and rejection cases in `codex-push-lib.test.mjs`. In `scripts/write-codex-push-proof.test.mjs`: the decision rules, the source-proof and chain rules, and an end-to-end throwaway-repository run of the real script. That run covers a docs-only carry accepted for the new base only, an edited merge commit refused, a stale source refused, and a code-vs-code merge routed to the collision check.
