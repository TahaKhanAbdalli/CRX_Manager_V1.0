## 2026-10-23 — Product brands: new brands wait for the list to refresh after an unclear save (step 1, PR A)

**What changed.** A Codex App review of PR #1050 (head `9d133c4c4`) found a way to add one brand twice. When saving a new brand fails without a clear answer (the reply was lost, so it may have been saved), the form locks as sent. But Cancel cleared that lock, and Add brand stayed on while the list was still refreshing, so an admin could reopen the form, change the name and save a second brand before the list showed the first. Add brand and the "Named in the product name" suggestions are now off whenever the product's own brand list is loading or failed to load, and the list is marked as loading the moment a save attempt ends. A new brand can only be started once the refreshed list shows what was actually saved.

**Proof.** A new ProductBrandsSection test (an unclear save, then Cancel) fails on the old code and passes now: Add brand and the suggestion stay off until the refresh lists the saved brand, and no second save is sent.

**Follow-up (Codex App on `1516e0afd`).** Cancelling an unclear new-brand save also retires that save's retry key. Before, entering the same details again later (say, after renaming the brand that was saved) reused the old key: the server replayed the earlier save and the app said "Brand added" when nothing was added. Now that later entry is a new request. A second test (unclear save, Cancel, the same details again) fails on the old code and passes now.

**Follow-up (Codex App on `18323785d`).** The same fix for Copy from another product. A copied brand whose save failed keeps its retry key, so a retry replays a save that did land. Once a refresh lists that brand on this product, the copy is settled and its key is retired. Before, copying the same source brand again later (after renaming the copy, say) replayed the old save: the app said "Copied 1 brand" when nothing was added. A third test (a failed copy that did land, a rename, then the same copy again) fails on the old code and passes now.

**Follow-up (Codex App on `cdd527025`).** Copy from another product now re-reads the source product's brands just before copying. If any chosen brand was edited or retired there since the list was shown, nothing is copied: the admin sees "changed since they were listed" and the dialog reloads with the current details. Before, the old EPA number, manufacturer or sourcing status could be copied. A fourth test (the source brand changes before Copy is clicked) fails on the old code and passes now.
