## 2026-10-19 - List pages: a multi-page read is confirmed by a matching second read

Closes the residual Mason accepted when PR #959 merged: an insert and a delete landing between two page reads kept the row count equal, so a list over 1,000 rows could show a just-deleted record and miss a just-added one (or, with a sort-date edit, miss a record that existed throughout). `fetchAllRows` in `src/lib/pagedRead.ts` now returns a read that took more than one request only once two back-to-back whole reads match row for row, every field included and array fields in order (so a field edited between pages cannot mix old and new values); disagreeing or wrong-count reads restart the confirmation and are retried within the existing three attempts and then shown as the "list changed while loading" error. A list that fits in one request is still read once (it now stops after that request instead of asking for an empty overlap page). Frontend only, no migration; Deliveries, Reports and Sales Reports are unchanged (their own follow-up). Live check with a temporary 10-row page: Vendors 11, Orders 1 and Invoices 11 matched the database.
